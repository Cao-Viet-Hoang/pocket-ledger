# i18n rules — Pocket Ledger

Two locales: `en` (default / fallback) and `vi`. They live in `locales/en.json` and `locales/vi.json`. Both files must contain the **same set of keys**. Language is persisted in `localStorage` as `pl.lang`.

## Invariants

1. **Every user-visible string is a translation key.** No hardcoded English/Vietnamese in JS, HTML attributes, or CSS `content:`.
2. **Every key exists in both locale files.** CI doesn't enforce this — humans do. If you add a key to `en.json`, add it to `vi.json` in the same change.
3. **Static markup in `index.html`** uses `data-i18n="key"` (for text content), `data-i18n-placeholder="key"`, or `data-i18n-aria="key"`. `I18n.applyTranslations(document)` swaps them on boot and on language change.
4. **Dynamic markup** built inside a page / form uses `I18n.t('key')` directly; the router calls `I18n.applyTranslations(container)` after each page render, but inline template-literal strings won't be re-translated, so always use `I18n.t` there.
5. **Interpolation** uses `{name}` placeholders: `I18n.t('time.dueIn', { n: 3 })`. Keep placeholder names the same across locales — the key `time.dueIn` must use `{n}` in both `en` and `vi`.

## Key namespaces (use these; don't invent new top-levels)

| Namespace | Purpose | Examples |
|---|---|---|
| `brand.*` | App identity | `brand.tagline` |
| `nav.*` | Sidebar / route names | `nav.dashboard`, `nav.accounts` |
| `page.{route}.subtitle` | Topbar subtitle per page | `page.dashboard.subtitle` |
| `action.*` | Buttons (`add`, `edit`, `delete`, `save`, `cancel`, `confirm`, `close`, `search`, `viewAll`, `configure`) | `action.add`, `action.viewAll` |
| `action.add.*` / `action.edit.*` / `action.delete.*` | Entity-specific verbs | `action.add.transaction`, `action.delete.savings` |
| `form.*` | Form validation errors | `form.amountRequired`, `form.nameRequired` |
| `toast.*` | Toast messages | `toast.saved`, `toast.deleted` |
| `confirm.*` | Confirm-dialog body text | `confirm.deleteTransaction` |
| `dash.*` | Dashboard-only labels and hints | `dash.currentBalance`, `dash.receivable.hint` |
| `txn.*` | Transactions vocabulary (type, categories UI, ranges, sorts) | `txn.income`, `txn.range.30d` |
| `cat.*` | Category display names | `cat.food`, `cat.salary` |
| `loan.*` | Lending & borrowing shared terms | `loan.principal`, `loan.status.overdue` |
| `people.*` | People page | `people.totalOwed`, `people.transactions` |
| `reports.*` | Reports page | `reports.incomeVsExpense`, `reports.noData` |
| `account.*` | Accounts page / entity | `account.type.bank`, `account.totalBalance` |
| `savings.*` | Savings page / entity | `savings.principal`, `savings.filter.active` |
| `transfer.*` | Transfer flow | `transfer.sameAccount`, `transfer.insufficientBalance` |
| `setup.*` | First-run Firebase connect | `setup.username`, `setup.errConfig` |
| `app.*` | App-level states | `app.connecting` |
| `time.*` | Relative-time strings with `{n}` | `time.daysAgo`, `time.overdueBy` |
| `person.*` | Person form labels | `person.name`, `person.phone` |

## When you add a new key

1. Decide the namespace from the table above. If nothing fits, raise the question — don't silently add a new top-level.
2. Add the key + English string to `locales/en.json`.
3. Add the same key + a natural Vietnamese translation to `locales/vi.json`.
4. Reference it via `I18n.t('…')` or `data-i18n="…"` — never inline the string.

## When you remove a feature

- Remove the key from **both** locale files.
- Grep for the key across `js/`, `index.html` and remove stale references.

## When you rename a route

- Update `ROUTES` in `router.js`.
- Update the `<nav>` entries in `index.html`.
- Register the page as `Pages.<newRoute>` and update `page.<newRoute>.subtitle` + `nav.<newRoute>` in **both** locale files.

## Notes

- Vietnamese strings may be longer than English — check that your layout doesn't break with `vi` selected.
- Don't embed HTML in locale strings. If you need emphasis, wrap `I18n.t(…)` output in markup at the call site.
- Don't translate category / entity **ids** — only their display labels via `nameKey` (e.g. `cat.food`).
